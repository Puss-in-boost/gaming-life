# V1.9 Adventure Camp — 首页体验改版

## 目的

减少「打开游戏先做管理工作」的挫败感。首页先突出一次真实的行动，再展示奖励、足迹与可选工具。以少操作、真实反馈为原则；不做未经确认的任务完成或金币发放。

## 体验变化

- 第一屏：CSS 绘制的静态营地画面、当前角色等级、真实 XP、冒险币、唯一今日主线、可操作的开始按钮。
- 对未开始任务，「▶ 开始」调用现有 `saveProgress(t,'doing','')`；开始**不发放 XP**。进行中任务可直接打开原有进度表单。
- 只有「✓ 确认完成」才触发原有 completion 的奖励结算；保留撤销完成逻辑。
- 空白/无可继续主线时：一行输入发布初始任务。默认一次性主线 +20 XP、10 金币，**不自动完成**、不填入任何用户私人任务。
- 备用主线、长期章节、ChatGPT 任务包、日志等保留完整入口，但改为可展开区域。自由支线仍最多两项。
- 新增「冒险足迹」：过去七天是否存在实际完成事件，不要求连续签到，不启用惩罚，也不写入新状态。
- 仅新增 `adventure.css` 前端样式，无数据库结构或云端同步协议改动；离线缓存包括新 CSS，缓存版本更新。

## 隐私与兼容

不改变 `state.version`、`migrate`、`state.privatePacks`、Supabase RLS、CAS 逻辑；不向公开仓库提交个人任务/存档。不覆盖线上 `main` 分支。已有存档完全依赖原有存储和同步策略。

## 验收

1. 运行 `node tests/v17.test.mjs && node tests/v18.test.mjs && node tests/v19.test.mjs`，现有版本的回归须继续通过。
2. 在全新浏览器（没有旧存档）打开：看见空白开局，不会自动创建/完成任务；一行输入可创建第一项任务。
3. 点击「开始」：变成进行中但经验、冒险币、完成日志不增加；点击「更新进度」仍可填写记录。只有点击确认完成才结算。
4. 在已保存旧任务的电脑验证 XP、金币、章节、私人任务包没有消失，主线/并行主线与金币撤销规则保持一致。
5. 手机端确认首页布局、按钮可点、底部导航与云端冲突提示可见；离线状态确认 `adventure.css` 已被缓存。
6. 在真实 Supabase 账户登录及两端同步进行人工验收（自动化单元测试不能替代生产数据库测试）。
