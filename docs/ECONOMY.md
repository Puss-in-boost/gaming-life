# V1.3 游戏经济与个人预算说明

## 动机与约束

奖励系统适用于多种生活目标，不应把正常休息、娱乐或必要消费设为必须解锁的权利，也不要用金币驱动过度工作与训练。

## 奖励收入

- XP 用于角色等级；冒险币独立记录为 **完成事件当时** 的 `coins`，币额不会因为任务日后被修改而重算。
- 例如50 XP主线可发25币、15/20 XP 支线可发8/10币；导入任务包可显式给 `coins: 0..80`。
- 普通任务奖励币的日累计上限60、周累计上限180；币额按实际完成顺序结算，达到上限后新任务仍可获得对应 XP。
- 任务撤销会撤回当次 XP 与币。如果余额已被兑现消费、撤回会导致负币数，则拒绝撤销，防止账本穿透。
- BOSS 完成时固定快照额外冒险币，只有确认阶段真实达成才发放。

## 奖励兑换与预算

- 默认额外消费预算每月 ¥30，可由用户主动调整为 ¥0–300 的整数。该上限只是示范值，应用**不建议必须消费**。
- 每个奖励有币价 `price` 和估计人民币支出 `rmb`。免费奖励的 `rmb=0`。
- 兑换前必须同时检查 **可用冒险币** 和 **本月可用人民币预留预算**，然后让用户确认。
- 付费奖励的人民币金额仅是预算预留；实际购物与记账并非本应用所执行，也不会联动 You-jile。
- 取消未享受的奖励可退币与释放预算预留；已享受不可退。
- 消费预算按**兑换月**计算，不是银行卡余额，跨月不会滚动结余。
- 自定义奖励需要手动填写估算人民币预算，默认 0；涉及花钱时应设成真实估算金额。

## 旧版升级（V1.2 → V1.3）

旧版 V1.2 把 XP 按 1:1 形成奖励币，且兑奖记录字段是 `cost`。首次加载新版本，执行一次幂等迁移：

1. 冻结旧余额 `max(0, old totalXP - old noncancelled redemption cost)` 为 `legacyCoinCredit`。
2. 把既有事件和 BOSS `coins` 置为 `0`，避免按新币率重复计算；保留历史 XP 与里程碑。
3. 旧兑换转为历史记录 `legacy:true`，金额记录保留，并不二次从新账本扣除。没有状态的旧兑换视为已兑现。
4. 保留旧奖励（转成统一 `price` 格式），追加 V1.3 新奖励选项，不删除自定义记录。
5. 设 `rewardEconomyVersion:2`；重复刷新或重新载入不重复迁移。

如果取消一笔迁移后的待享受旧兑换，将它的旧币价退回冻结账户。导出 JSON 包含迁移后的完整账本。

## 奖励种类

- 免费：游戏主题夜、免费观影、城市探索和游戏称号。
- 低价消费：预算约 ¥12 的小食、¥25 的额外平价美食、¥20 的简单线下娱乐。
- 未来愿望：衣鞋、数码、游戏设备、远途旅行。先收藏计划，确认有经济余力后再主动配置，无默认购买引导。

## 边界

每天主线 1 项、支线最多 2 项是界面建议，不是强制阻止用户记录更多真实成果；真正限制刷币的是完成频率与金币日/周上限。日常娱乐不作为需要购买的权限。离线数据不等于可靠备份，正式跨设备使用前需要 Supabase 身份隔离与同步冲突处理。
