# Gaming Life V1.4 · 双主线与任务进度

## 为什么需要这层

现实中的论文、求职和职业成长往往持续多日。不能把「已经有成果，等待最终确认」当作彻底没有开始，也不能因为记录了部分进展就提前发放全部经验和金币。

## 状态

| 状态 | 触发 | 奖励 | 说明 |
| --- | --- | --- | --- |
| 未开始 | 默认状态 / 手动清空 | 0 | 还未留下本周期进度 |
| 进行中 | 玩家更新进度 | 0 | 可以填写本次实际成果 |
| 待确认 | 玩家更新进度 | 0 | 需要核对信息、确认完成标准或等待外部反馈 |
| 已完成 | 点击「完成任务」 | 按任务当前 XP/金币规则结算 | 记录完成事件；只能对未完成周期结算一次 |

「待确认」不是自动 AI 审核，不代表第三方已审批。撤销已完成事件，若允许撤销，任务恢复之前的进度状态。金币不足以撤销时，遵循 V1.3 的防透支逻辑。

## 进度存储

`state.questProgress` 是以 `taskId@period` 为键的映射，每个记录包含 `status`、`note`、`updatedAt`：

- `once`：`taskId@once`，跨天延续；
- `daily`：`taskId@YYYY-MM-DD`，每天重置显示但保留历史日志；
- `weekly`：`taskId@YYYY-MM-DD`，日期为本周周一。

`state.progressHistory` 只保留最近最多150项操作足迹，附带标题、状态、笔记和日期，供日志和用户主动复制状态使用。此记录只在本机浏览器保存，除非用户自行导出或发送给 ChatGPT。

## 两条主线

- `state.mainId` 表示**今天优先**的主线。
- `state.secondaryMainId` 表示备选的并行主线。如果没有有效指定，界面从其他活跃主线中选取一条作为备选。
- 切换主线不停止另一条主线，也不会扣经验。
- 导入包含 `focusId` 的任务包时，以新主线为优先主线，把此前活跃主线保留为并行主线。
- 导入求职冲刺任务包需用户主动预览、确认，**不自动替用户认定任何求职任务已经完成**。

## 测试范围

本地 Chromium 交互验收包含：已有存档迁移、求职包预览与导入、双主线切换、记录「进行中」/「待确认」、刷新后继续保留、未完成不加 XP、完成结算一次与撤销、历史足迹、手机窄屏显示。上线后仍需检查 GitHub Pages 发布情况。
